# Shopro AI 后台管理 AI 整改执行任务书

> 文档版本：V1.0  
> 编制日期：2026-08-20  
> 目标读者：后续负责修改当前仓库的 AI 编码代理或研发人员

## 1. 执行目标

在现有 Vue 3 + TypeScript + Element Plus + Axios + MSW 项目中，按阶段完成运营后台整改。优先实现真实的 Mock 业务规则和端到端运营闭环，再为 Spring Boot 接入提供稳定契约。

除非用户明确改变范围，执行者不得直接创建真实 Spring Boot、数据库、支付或 AI 服务。

## 2. 开始开发前必须阅读

按以下顺序完整阅读：

1. `front-README.md`
2. `功能说明文档.md`
3. `技术架构与项目结构说明.md`
4. `docs/01-后台管理整改总体方案.md`
5. `docs/02-后台管理目标数据模型与接口规范.md`
6. 当前阶段涉及的全部源码文件

如文档和当前代码不一致，以用户最新明确要求为最高优先级；其次以当前代码事实为准，并在交付说明中记录差异。

## 3. 强制执行规则

1. 一次只实施本任务书中的一个阶段，除非用户明确要求连续完成多个阶段。
2. 修改前检查工作区状态，保留用户已有修改，不覆盖无关文件。
3. 页面不得直接读取或修改 localStorage、种子数据或 Mock 数据库。
4. 页面只通过 `src/api/` 调用业务接口。
5. Mock handler 不得直接堆积全部业务规则；积分、任务、支付等规则放入独立领域函数。
6. 不得继续扩展 `any`。新接口参数、响应、表单和页面状态必须使用明确类型。
7. 不得继续使用一个通用 `Status` 表达全部领域状态。
8. 不得直接修改积分余额，必须创建积分流水并在同一事务中更新余额。
9. 任务重试不得覆盖旧尝试，必须创建新 `JobAttempt`。
10. 支付状态不得由运营通过通用状态按钮修改。
11. 审核必须基于 `RiskEvent`，不得把所有私有内容放入人工待审核。
12. 敏感写操作必须有二次确认、原因和审计记录。
13. 所有 Dashboard 指标必须由 Mock 数据实时计算，禁止新增硬编码经营数字。
14. Demo 专属功能必须受 `VITE_APP_MODE=demo` 控制。
15. 每个阶段结束后必须执行 `pnpm build`；构建失败不得宣布完成。
16. 未经用户要求不得提交 Git commit、推送远程仓库或删除用户文件。

## 4. 当前代码基线

当前需要重点整改的集中式文件：

| 文件 | 当前问题 |
| --- | --- |
| `src/types/index.ts` | 全部类型集中、字段过少、通用 Status 混用 |
| `src/api/index.ts` | 全部接口集中且大量使用 `any` |
| `src/mocks/handlers.ts` | 种子、存储、业务规则和接口处理器全部集中 |
| `src/router/index.ts` | 动态字符串路由，无法表达分组、权限和元数据 |
| `src/layouts/AdminLayout.vue` | 菜单固定、无全局搜索和权限过滤 |
| `src/views/UsersView.vue` | 直接用 prompt 修改积分，无详情和流水 |
| `src/views/JobsView.vue` | 重试覆盖原任务，无工作流和执行历史 |
| `src/views/ContentsView.vue` | 只有状态切换，无风险详情和理由 |
| `src/views/OrdersView.vue` | 指标硬编码、订单只读且无详情 |
| `src/views/DashboardView.vue` | 指标结构过于简单，图表实例无统一管理 |
| `src/views/SystemView.vue` | 健康、审计和 Demo 重置混合在同页 |

当前基线 `pnpm build` 可以成功，但会出现 chunk 超过 500 kB 的警告。该警告应记录为技术债，不能通过单纯调大 Vite 警告阈值掩盖。

## 8. 阶段 C：AI 工作流和任务执行

- 工作流详情展示全部子任务和执行尝试。
- 支持用户、企业、任务状态、任务类型、模型、错误分类、日期和需人工处理筛选。

### 任务 `AI-002`：重试规则

实现：

- 仅 `retryable=true` 且不存在运行中尝试时允许重试。
- 新建 `JobAttempt`，旧失败尝试不变。
- 更新 Job 的 `currentAttemptId` 和 `attemptCount`。
- 运营人工重试不重复扣用户积分。
- 写入审计并返回更新后的 Job 和新 Attempt。

### 任务 `AI-003`：取消规则

实现：

- 点击取消先进入 `CANCEL_REQUESTED`。
- Mock 延时推进为 `CANCELLED` 或模拟取消失败。
- 已成功、已失败、已取消任务不允许再次取消。
- 记录供应商是否支持取消以及最终计费处理。

### 任务 `AI-004`：失败退回积分

实现：

- 最终失败且 `creditsCharged > creditsRefunded` 时生成自动退款流水。
- 固定场景保留“自动退款失败”，用于工作台告警和人工处理。
- 人工补偿完成后清除该待办，但保留原异常和处理历史。

### 阶段 C 验收场景

1. 固定视频失败任务显示供应商超时和第一次执行记录。
2. 点击重试产生第二次执行记录，第一次仍保持失败。
3. 重试成功后 Workflow 状态、成本和输出正确更新。
4. 用户积分没有因人工重试被重复扣除。
5. 不可重试错误的按钮不可用，并显示明确原因。
6. 取消动作经过请求中状态。
7. `pnpm build` 通过。
